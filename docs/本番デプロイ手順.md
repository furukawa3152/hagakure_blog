# 本番環境を変更するには

本番（`hagakurepgm.net`）に変更を反映する手順です。運用形態（Docker / 直接実行 / ホスティングの自動デプロイ）に合わせて該当する流れだけ行ってください。

---

## 1. コードを本番に反映する

**Git でデプロイしている場合**

- 本番サーバーまたは CI で `git pull` する  
- または main に push すると自動デプロイされる場合は、push だけでよい

**手動でファイルを置いている場合**

- 変更したファイルだけ本番サーバーにアップロードする  
- 今回の変更例：
  - テンプレート: `blog/templates/blog/blog_page.html`
  - 静的: `blog/static/css/blog_page.css`
  - Python: `blog/utils/sheet_logger.py`, `blog/signals.py` など

---

## 2. 静的ファイルを集約する（本番で Django を直接動かしている場合）

テンプレートや CSS/JS を変えた場合は、本番で次を実行します。

```bash
python manage.py collectstatic --noinput
```

※ Docker でビルドし直す場合は、イメージ内で既に `collectstatic` が走っているので不要です。

---

## 3. マイグレーション（モデルを変更した場合のみ）

**モデル（DB）を変えていない**場合は不要です。

モデルを追加・変更した場合は本番で実行します。

```bash
python manage.py migrate --noinput
```

※ Docker の CMD で起動時に `migrate` している場合は、コンテナ起動で自動実行されます。

---

## 4. アプリを再起動する

- **Docker の場合**  
  - イメージをビルドし直してコンテナを立て直す  
  ```bash
  docker build -t hagakure_blog .
  docker stop <コンテナ名>
  docker run -p 8000:8000 hagakure_blog
  ```
  - または `docker-compose up -d --build` など

- **systemd / Gunicorn などで直接動かしている場合**  
  ```bash
  sudo systemctl restart gunicorn   # 例
  ```

- **Render / Railway など**  
  - 再デプロイ（git push や「Redeploy」）で自動的に再起動されます。

---

## チェックリスト（今回のような「コード・テンプレート・静的だけ」の変更）

| やること | 必要？ |
|----------|--------|
| コードを本番に反映（git pull やファイル更新） | ✅ 必須 |
| `collectstatic` | ✅ 本番で Django を直接動かしている場合 |
| `migrate` | ❌ モデル変更がなければ不要 |
| アプリの再起動 | ✅ 必須 |

---

## 本番設定の注意（README より）

- 本番用設定: `mysite/settings/production.py`
- 本番では **`DEBUG = False`** に変更してからリリースすること（現在は True のままの想定なので要確認）。
